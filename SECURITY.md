# Security Policy

## Supported Versions

Only the latest version of KAT gets security fixes. If you are running
something old, update first, the bug might already be fixed.

| Version | Supported          |
| ------- | ------------------ |
| 0.2.x   | :white_check_mark: |
| 0.1.x   | :x:                |
| < 0.1   | :x:                |

## Reporting a Vulnerability

Do NOT open a public GitHub issue for a security bug, and do not post
it publicly anywhere. If a vulnerability is public before it is fixed,
anyone can use it in the meantime, and that helps nobody.

Report it privately instead:

1. Join the Discord: https://discord.gg/SSbX6eat9j
2. Open a private ticket in the server and put the report in there.
   Only you and the staff can see a ticket.
3. In the ticket, say what is wrong. If you can, add detail on what
   you think the bug actually is, where it is, and how someone would
   use it. If you are not sure about the details, that is fine too,
   just say what is wrong as best you can and it will go into
   investigation from there.

Normal bugs that are not security problems, and normal text stuff
like suggestions or wording fixes, are fine in public. GitHub issues
or the bug reports channel both work for those. The private ticket
rule is only for vulnerabilities.

## What Happens Next

Your report gets investigated first, before anything is done with it.

If you send a code solution with your report, thank you, but it will
not just be dropped in as is. It gets investigated before it is used,
counter weighed against other ways of fixing the same problem, and
thought about properly, because sometimes there is a better solution
and sometimes a fix causes a new bug somewhere else. If your solution
is the best one it will be used, and if a different fix is chosen
instead, the staff can tell you why in the ticket.

Please give us time to fix it before you talk about the vulnerability
anywhere public. Once a fix is out, it is fine to talk about.
